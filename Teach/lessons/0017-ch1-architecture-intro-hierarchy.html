Lesson 17: Chapter 1 — Introduction & Architectural Hierarchy

เป้าหมายของบทที่ 1: เข้าใจความสำคัญของสถาปัตยกรรมซอฟต์แวร์ หลีกเลี่ยงกับดัก "Big Ball of Mud" และแยกแยะลำดับชั้นระหว่าง Architecture Style, Architecture Pattern และ Design Pattern ได้อย่างแม่นยำ

Chapter 1 Goal: Understand why software architecture matters, avoid the "Big Ball of Mud" trap, and master the conceptual hierarchy between Architecture Styles, Architecture Patterns, and Design Patterns.

1. The Big Ball of Mud Anti-Pattern

Mark Richards ชี้ให้เห็นว่า นักพัฒนามักเริ่มเขียนโค้ดทันทีโดยไม่มีการวางสถาปัตยกรรมอย่างเป็นทางการ ผลลัพธ์คือส่วนประกอบต่าง ๆ เชื่อมโยงกันอย่างไร้ทิศทาง กลายเป็นก้อนสปาเกตตีขนาดใหญ่ที่เรียกว่า "Big Ball of Mud"

It is all too common for developers to jump straight into coding without an architecture in place. This results in tightly coupled, brittle components known as a Big Ball of Mud.

  • เปราะบาง (Brittle): แก้ไขโค้ดที่จุด A แต่ระบบกลับพังที่จุด Z
  • ขาดทิศทาง (Lack of Vision): ไม่มีใครตอบได้ชัดเจนว่าระบบจะรองรับ Scalability, Performance หรือ Availability ได้มากแค่ไหน

2. ลำดับชั้น 3 ระดับของสถาปัตยกรรม (The 3-Tier Hierarchy)

┌─────────────────────────────────────────────────────────────────────────┐ │ 1. Architecture Style (ภาพรวมมหภาคของระบบ - Macro Structure) │ │ กำหนดลักษณะภาพรวมและพฤติกรรมของระบบ (System-wide Characteristics) │ │ ตัวอย่าง: Layered, Microservices, Event-Driven, Microkernel, Space-Based│ └────────────────────────────────────┬────────────────────────────────────┘ │ ประกอบด้วย (composed of) ▼ ┌─────────────────────────────────────────────────────────────────────────┐ │ 2. Architecture Pattern (บล็อกเชิงโครงสร้างสำหรับแก้ปัญหาเฉพาะด้าน) │ │ แพทเทิร์นโครงสร้างระดับระบบที่นำไปใช้ภายใน Style เพื่อแก้โจทย์ทางสถาปัตยกรรม │ │ ตัวอย่าง: CQRS, Saga Pattern, Event Sourcing, Circuit Breaker │ └────────────────────────────────────┬────────────────────────────────────┘ │ สร้างด้วย (implemented with) ▼ ┌─────────────────────────────────────────────────────────────────────────┐ │ 3. Design Pattern (การออกแบบโค้ดระดับ Class & Object) │ │ รูปแบบการจัดวางโค้ดและคลาสในระดับ Source Code │ │ ตัวอย่าง: Builder, Factory Method, Strategy, Observer, Adapter │ └─────────────────────────────────────────────────────────────────────────┘
💡 ตัวอย่างความสัมพันธ์เชื่อมโยง: คุณสามารถใช้ Builder Design Pattern ในการเขียนโค้ดเพื่อสร้างคำสั่งใน CQRS Architecture Pattern ซึ่งถูกบรรจุเป็นส่วนหนึ่งของระบบ Microservices Architecture Style!

3. Hybrid Architecture Styles

ในโลกของการทำงานจริง ไม่มี Architecture Style ใดเพียงสไตล์เดียวที่ตอบโจทย์ธุรกิจได้ครบทั้งหมด การผสมผสานสไตล์เข้าด้วยกัน (Hybrids) จึงเป็นเรื่องปกติ เช่น:

In the real world, no single style solves every business problem. Hybrid architectures are common, such as:

  • Event-driven Microservices: ใช้ Events ในการสื่อสารระหว่าง Microservices
  • Space-based Microservices: หน่วยประมวลผลของ Space-based ถูกเขียนเป็น Microservices
  • Event-driven Microkernel: การส่งสัญญาณแบบ Event ระหว่าง Core System และ Remote Plug-ins
